# Architecture
Covers: layering, feature layout, dependency direction, use cases, repositories, datasources
Does not cover: where each kind of file goes (file-placement.md), error types (errors.md)
Rule: `lib/features/<f>/{data,domain,presentation}`, shared `lib/core/`, entry `lib/app/`. Feature = capability, not a table (interests/follows live in `profile`). Repository / entity / use case only when needed.
Datasource per concern: `abstract interface class` + `final class` Supabase adapter in ONE file, `@LazySingleton(as: …)`, returns wire models (or void) and throws `Failure`.
Repository only where sources are coordinated: `ProfileRepository` (abstract + Impl one file; remote + `ProfileLocalDatasource`, network-first, local fallback only on lost connection; maps model -> entity privately; models never import `domain/`).
Features trade ONLY via `domain/use_case/` (`@injectable`, named by intent, smallest return type). `auth` -> `profile` one way; `profile` never imports `auth`/`splash`; nobody imports another feature's datasource/repository/model/entity. Sign-up flow lives in `auth/presentation`.
Exception [user, 2026-10-13]: a `domain/entity` type that a use case returns is part of that use case's public API and may be imported by the consuming feature (e.g. home uses `PostEntity`, `StoryRailItemEntity`). Models, datasources and repositories stay private.
Exception [user, 2026-10-14]: the post feature's list widgets are public presentation exports: `PostCard`, `PostOptionsFlow`, `PostVisibilitySheet`, `HiddenPostRow`, `PostVideoScope`, `PostActionsCubit` (with `PostActionsState`, `PostRow`; one per list screen: like, save and the options sheet's actions) and the plain types `PostCardData`, `PostCardCallbacks`, `PostCardMedia`, `PostOptionsData`, `PostOptionsActions` and the `ContentAudienceDisplay` extension (`features/post/presentation`) may be imported by features that list posts (home now; profile, saved, search later). Post's datasources, models and cubits stay private. See `docs/specs/post/02-components.md`.
Never: feature per table, pass-through use cases, cross-feature datasource imports.
Example: lib/features/splash (calls IsSignedInUseCase + GetSignupStepUseCase); lib/features/profile/data/repository
Exceptions: onboarding has no data layer beyond a local flag datasource.
Story: `features/story` has `StoriesDatasource` (Supabase adapter), `StoryMediaUploader` (streamed `http` upload with byte progress) and a `StoryUploadRepository` (singleton: one background post at a time, `status` stream idle/uploading/failed/done, retry). Public API: `GetStoryRailUseCase` -> `StoryRailItemEntity`, `WatchStoryUploadUseCase` -> `StoryUploadStatus`, plus the other use cases in `domain/use_case`. Gallery saves go through core `GalleryService` (`gal`).
Story viewer: `StoryViewerCubit` (freezed state) holds person/story position, pause reasons, like and the 1 s seen timer; bar/video timing lives in the widgets (`StoryMedia`, a `ValueNotifier<double>` progress). One `VideoFlux` per person page (`StoryVideoController` over `video_player`). Route `/story/:authorId` is matched by prefix in `AppRouter`.
Post: `features/post` has `PostsDatasource` (home feed page, signed media links, files in `post-media/{uid}/{postId}/`, `create_post`); public use cases `GetHomeFeedUseCase` -> `FeedPageEntity`/`PostEntity`, `SignPostMediaUrlsUseCase`, `CreatePostUseCase` (uploads only missing files, removes them if the insert fails). Post-only actions (like, save, hide, comments toggle, delete): `PostActionsDatasource` + use cases in `features/post` (their use cases are what Home, profile and the saved list call; `DeletePostUseCase` removes the row, then the files through the shared `RemoveMediaFilesUseCase`). Report, change audience and mute are the shared use cases in `lib/shared/content`. Photos are resized at pick time with `ImageResizePreset.active` (`lib/core/enums`), not in `CreatePostUseCase`.
Shared code [user, 2026-10-14]: `lib/shared/<concept>/{data,domain}` holds business data and domain used by 2+ features, with generic names; features import `shared` and `core`, `shared` imports only `core`, `core` never imports `shared`. Shared content actions: what story, post and short do the same way lives in `lib/shared/content/{data,domain}` with generic names, and feature cubits call its core use cases (never the datasource). `ContentKind { post, story, short }`, `MuteScope { posts, stories }` (posts and stories are muted on their own), `ContentAudience` (public / followers / close_friends / only_me; story only offers followers and close_friends). Datasources: `ContentActionsDatasource` (RPCs `report_content`, `set_content_audience`, `set_mute`), `MediaFilesDatasource` (best-effort file cleanup in `post-media`). Use cases: `ReportContentUseCase`, `SetContentAudienceUseCase`, `SetMuteUseCase`, `RemoveMediaFilesUseCase`. Nothing named after one feature goes here. Post-only actions (like, save, hide, comments toggle, delete) stay in `features/post` (`PostActionsDatasource`, its use cases are post's public API). Story keeps its rail refresh: `StoriesDatasource.notifyRailChanged()` after a mute.
Account privacy for new content: shared `GetPrivacyUseCase` (private account + default audience, never Public when private) and `SaveDefaultAudienceUseCase` over `PrivacyDatasource` (`profiles.is_private`, `profiles.default_post_visibility`), in `lib/shared/content` because post, short and Settings > Privacy all need them; the shared `GetAudienceSummaryUseCase` (`lib/shared/content`, `AudienceDatasource` over `audience_summary`) gives the followers / close-friends / hidden counts to story and post. The one-time notice flag is `post`'s `VisibilityNoticeDatasource`.
Feed refresh [user, 2026-10-14]: `FeedRefreshRepository` (post, singleton signal) tells Home to load again. Producers: `CreatePostUseCase` (a post was shared) and the shell's `RequestFeedRefreshUseCase` (Home tapped while open); consumer: `WatchFeedRefreshRequestsUseCase`, listened to by Home's feed, rail and bell cubits.
Activity [user, 2026-10-14]: `features/activity` is the notifications feature (migration `20261014120000_notifications.sql`: `notifications`, `activity_feed`, `activity_unread_count`, `mark_activity_read`, push prefs, device tokens). Applied to the project 2026-10-15. Built so far: `ActivityDatasource.getUnreadCount` and the public `GetUnreadActivityCountUseCase` (unread notifications + follow requests, Home's bell dot); the Activity screen, feed, push and realtime come later. Follow requests themselves stay in `features/follow`.
Shared places [user, 2026-10-14]: `lib/shared/places/{data,domain,presentation}` holds the place picker for any feature (post now, story later): `PlacesRepository` (the `places` Edge Function + recent places on the device), `PlaceEntity`, the primer flag, and the Add location screen with its Cubit and widgets, opened at `AppRoutes.pickPlace` with the place already chosen as the argument and answering with a `LocationChoice`. It extends the `shared` layout with a `presentation/` folder because the screen itself is reused; its widgets stay inside it until a second feature needs one of them (then it moves to `core/widgets`). The device position and permission are `core/services/location_service.dart`.
