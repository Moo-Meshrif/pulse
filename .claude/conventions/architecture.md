# Architecture
Covers: layering, feature layout, dependency direction, use cases, repositories, datasources
Does not cover: where each kind of file goes (file-placement.md), error types (errors.md)
Rule: `lib/features/<f>/{data,domain,presentation}`, shared `lib/core/`, entry `lib/app/`. Feature = capability, not a table (interests/follows live in `profile`). Repository / entity / use case only when needed.
Datasource per concern: `abstract interface class` + `final class` Supabase adapter in ONE file, `@LazySingleton(as: …)`, returns wire models (or void) and throws `Failure`.
Repository only where sources are coordinated: `ProfileRepository` (abstract + Impl one file; remote + `ProfileLocalDatasource`, network-first, local fallback only on lost connection; maps model -> entity privately; models never import `domain/`).
Features trade ONLY via `domain/use_case/` (`@injectable`, named by intent, smallest return type). `auth` -> `profile` one way; `profile` never imports `auth`/`splash`; nobody imports another feature's datasource/repository/model/entity. Sign-up flow lives in `auth/presentation`.
Exception [user, 2026-10-13]: a `domain/entity` type that a use case returns is part of that use case's public API and may be imported by the consuming feature (e.g. home uses `PostEntity`, `StoryRailItemEntity`). Models, datasources and repositories stay private.
Exception [user, 2026-10-14]: the post feature's list widgets are public presentation exports: `PostCard`, `PostOptionsFlow`, `PostVisibilitySheet`, `HiddenPostRow`, `PostVideoScope`, `PostActionsCubit` (with `PostActionsState`, `PostRow`; one per list screen: like, save and the options sheet's actions) and the plain types `PostCardData`, `PostCardCallbacks`, `PostCardMedia`, `PostOptionsData`, `PostOptionsActions` and the `ContentAudienceDisplay` extension (`features/post/presentation`) may be imported by features that list posts (home now; profile, saved, search later). Post's datasources, models and cubits stay private. See `docs/specs/post/02-components.md`.
Never: feature per table, pass-through use cases, cross-feature datasource imports.
Example: lib/features/splash (calls IsSignedInUseCase + GetSignupStepUseCase); lib/features/profile/data/repository
Exceptions: onboarding has no data layer beyond a local flag datasource.
Story: `features/story` has `StoriesDatasource` (Supabase adapter) and a `StoryUploadRepository` (uploads a story's files and inserts the row, as a job of the shared publisher below). Public API: `GetStoryRailUseCase` -> `StoryRailItemEntity`, plus the other use cases in `domain/use_case`. Media upload [user, 2026-10-16, `docs/plans/media-upload-plan.md`]: story, post and short share one path in `shared/content`: `MediaFilesDatasource.upload` (streamed `http` with byte progress, upsert, retries dropped connections and 408/429/5xx up to 3 tries) `ContentMediaRepository` (sends a file and its video frame as `{folder}/{stem}.{ext}` + `{stem}_thumb.jpg`, skips files already there, checks `MediaPolicy` in `domain/policy`: per-kind video limits, as-is / shrink / reject; shrinks with core `VideoCompressService` over `flutter_compress`, keeping the copy until it is uploaded) and `ContentPublishRepository` (one background job per `ContentKind`, status `ContentPublishStatus` idle/publishing(progress)/failed/done, retry, discard; use cases `PublishContentUseCase`, `RetryPublishUseCase`, `DiscardPublishUseCase`, `GetPublishStatusUseCase`). Gallery saves go through core `GalleryService` (`gal`).
Story viewer: `StoryViewerCubit` (freezed state) holds person/story position, pause reasons, like and the 1 s seen timer; bar/video timing lives in the widgets (`StoryMedia`, a `ValueNotifier<double>` progress). One `VideoFlux` per person page (`StoryVideoController` over `video_player`). Route `/story/:authorId` is matched by prefix in `AppRouter`.
Post: `features/post` has `PostsDatasource` (home feed page, signed media links, files in `post-media/{uid}/{postId}/`, `create_post`); public use cases `GetHomeFeedUseCase` -> `FeedPageEntity`/`PostEntity`, `SignPostMediaUrlsUseCase`, `CreatePostUseCase` (uploads only missing files, removes them if the insert fails). Post-only actions (like, save, hide, comments toggle, delete): `PostActionsDatasource` + use cases in `features/post` (their use cases are what Home, profile and the saved list call; `DeletePostUseCase` removes the row, then the files through the shared `RemoveMediaFilesUseCase`). Report, change audience and mute are the shared use cases in `lib/shared/content`. Photos are resized at pick time with `ImageResizePreset.active` (`lib/core/enums`), not in `CreatePostUseCase`.
Shared code [user, 2026-10-14]: `lib/shared/<concept>/{data,domain}` holds business data and domain used by 2+ features, with generic names; features import `shared` and `core`, `shared` imports only `core`, `core` never imports `shared`. Shared content actions: what story, post and short do the same way lives in `lib/shared/content/{data,domain}` with generic names, and feature cubits call its core use cases (never the datasource). `ContentKind { post, story, short }`, `MuteScope { posts, stories }` (posts and stories are muted on their own), `ContentAudience` (public / followers / close_friends / only_me; story only offers followers and close_friends). Datasources: `ContentActionsDatasource` (RPCs `report_content`, `set_content_audience`, `set_mute`), `MediaFilesDatasource` (best-effort file cleanup in `post-media`). Use cases: `ReportContentUseCase`, `SetContentAudienceUseCase`, `SetMuteUseCase`, `RemoveMediaFilesUseCase`. Nothing named after one feature goes here. Post-only actions (like, save, hide, comments toggle, delete) stay in `features/post` (`PostActionsDatasource`, its use cases are post's public API). After a mute the viewer cubit fires `StoryRailChanged` on the `EventBus`.
Account privacy for new content: shared `GetPrivacyUseCase` (private account + default audience, never Public when private) and `SaveDefaultAudienceUseCase` over `PrivacyDatasource` (`profiles.is_private`, `profiles.default_post_visibility`), in `lib/shared/content` because post, short and Settings > Privacy all need them; the shared `GetAudienceSummaryUseCase` (`lib/shared/content`, `AudienceDatasource` over `audience_summary`) gives the followers / close-friends / hidden counts to story and post. The one-time notice flag is `post`'s `VisibilityNoticeDatasource`.
Events [user, 2026-10-15]: a signal with no state to keep (reload the feed, a post was saved, the rail changed) goes on the injected `EventBus` (`core/events/`). A Cubit uses `EventCubitMixin` (`fire`, `listenTo`, `syncState`; it returns its bus from `events`; listeners end on close), so no use case, repository or datasource is needed just to relay it. The event is a plain `Equatable` in the owning feature's `domain/event/` and is that feature's public API: `FeedRefreshRequested` and `PostSaved(PostEntity)` (post; fired by `ControlCubit` on a Home re-tap and by `AddEditPostCubit` after the create/edit use case returns the saved post; heard by Home's feed, rail and bell cubits), `StoryRailChanged` (story). A repository that holds state (a job, its retry) still sends its status on the bus: `ContentPublishRepository` fires `ContentPublishStatus` (it carries its `kind`, so `fireLatest` by type would not fit); a late screen reads its first state with `GetPublishStatusUseCase(kind)` and then listens, ignoring other kinds (`PostPublishCubit` for post, `StoryRailCubit` for story). `PasswordRecoveryTracker` keeps its own stream (it persists and holds one undelivered signal).
Activity [user, 2026-10-14]: `features/activity` is the notifications feature (migration `20261014213146_notifications.sql`: `notifications`, `activity_feed`, `activity_unread_count`, `mark_activity_read`, push prefs, device tokens). Applied to the project 2026-10-15. Built so far: `ActivityDatasource.getUnreadCount` and the public `GetUnreadActivityCountUseCase` (unread notifications + follow requests, Home's bell dot); the Activity screen, feed, push and realtime come later. Follow requests themselves stay in `features/follow`.
Places [user, 2026-10-14, moved from `shared` to `features` 2026-10-15]: `lib/features/places/{data,domain,presentation}` is a normal feature, the place picker that any feature (post now, story later) opens by route only; no other feature imports its widgets, cubit or data: `PlacesRepository` (the `places` Edge Function + recent places on the device), `PlaceEntity`, the primer flag, and the Add location screen with its Cubit and widgets, opened at `AppRoutes.pickPlace` with the place already chosen as the argument and answering with a `LocationChoice`. Its widgets stay inside it until a second feature needs one of them (then it moves to `core/widgets`). The device position and permission are `core/services/location_service.dart`.
